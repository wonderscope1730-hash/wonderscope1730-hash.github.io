Purpose and access

This is a private, operator-controlled creative-writing and research application, not a public service. When the operator authorizes Google Drive access, it requests https://www.googleapis.com/auth/drive.file to access files it creates or files specifically selected or shared with the application. It does not request full unrestricted Drive access.

Google user data used

The application may process the Google account's Drive identity/permission identifier, file IDs, file names, folder relationships, file types, sizes, and content of files selected for the writing workflow or created by the application. OAuth access and refresh credentials are used to authenticate authorized operations.

How data is used

Authorized Google Drive information and files are used for project file discovery within the granted scope, writing-artifact creation, version retrieval, integrity checking, and audit/recovery workflows. Google user data is not used for targeted advertising or sold to advertisers.

Storage and service providers

Writing files and versions are stored in the operator's designated Google Drive project area. Project code and certain evidence are stored in a private GitHub repository; operational state, hashes, and audit records are held in hosted PostgreSQL. Independently preserved backup copies may reside in the operator's designated Dropbox backup area. OAuth secrets are configured as protected GitHub Actions secrets and access tokens are handled in runtime memory. These providers process data according to their respective terms and security controls.

Third-party model processing

Specific private manuscript text may be submitted to a separately approved AI model provider to obtain creative-writing diagnostics. Such transmissions are subject to an explicit operator decision and the provider's applicable data-processing terms. A model evaluation is not authorization to publish a manuscript or to make its contents public.

Retention, versions, and deletion

Project artifacts are versioned and may be retained until the operator approves a change or deletion. Historical audit records and independently preserved backup snapshots may remain after an active copy changes. A single universal deletion period has not been established; recurring weekly backups should not be assumed active. For questions or to request an access or deletion review, contact the email above. Changes affecting protected records or backups require deliberate operator authorization.

Website visitors

These informational pages contain no sign-in form, advertising scripts, or application analytics. The static hosting provider may independently process basic web-server and security logs as described in its own policies.

Changes

This policy may be revised if the app's authorized scopes, processing, providers, or data handling change. Updated text will be reflected on this page before it is used to describe expanded practices.
